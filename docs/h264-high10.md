# Progressive H.264 High10 decoding

`H264DecoderFactory` decodes progressive 10-bit 4:2:0 and 4:2:2 I/P/B pictures
with CABAC or CAVLC and flat scaling lists. Frames use
`VideoPixelFormat.Yuv420P10` or `VideoPixelFormat.Yuv422P10`: planar Y, Cb and Cr
samples in the low ten bits of native-endian unsigned 16-bit words. Decoding,
seeking, cropping and timestamps use the existing public video session API.

The decoder retains ten-bit precision throughout reconstruction, motion
interpolation, weighted prediction and in-loop filtering. QP-prime values retain
the bit-depth offset; negative syntax QP values are accepted within the declared
precision. CABAC and CAVLC coefficient limits follow the bit depth. Pixel planes
use two bytes per sample, while coefficient-count, mode and reference metadata
retain their original compact storage. Publishing a frame shares the picture
pixel allocation without copying it into a second image buffer.

Spatial prediction and scalar filtering share typed arithmetic across byte and
word samples. Existing SIMD byte kernels remain in use for eight-bit decoding
and encoding. High-precision interpolation uses bounded stack tiles, including
border extension, without an image-sized temporary allocation. Weighted B
prediction scales each signed offset before rounding their average, as required
by H.264 equations 8-276 and 8-291 through 8-297.

## Independent verification

Eight FFmpeg 6.1.1/libx264 streams cover 4:2:0 and 4:2:2, CABAC and CAVLC,
QP1/22/45, multiple slices, I/P/B reordering, three GOPs and cropped coded borders.
The source includes all ten sample bits. All 192 decoded frames and 192 reverse
seeks match independently decoded reference pixels exactly. The checks also
verify presentation timestamps, durations, pixel formats, EOF and buffer release.
The first published frame is retained across subsequent decoding, every seek and
session disposal; its pixels remain unchanged until the caller releases it.

The same sequences pass in a standalone Native AOT executable, together with the
four eight-bit 4:2:2 reference streams. Independent scalar convolution checks cover
all luma and chroma interpolation phases, picture borders, extreme motion
coordinates, irregular block sizes and destination guards. Explicit weighted
prediction vectors include odd positive and negative offset sums. Transform tests
cover QP-prime 60 and 63; PCM tests cover native word storage and alignment.

The main managed test project passes all 4,465 tests; its H.264 selection contains
880 tests. A focused selection passes 53
tests with hardware intrinsics disabled. Reproduction commands and reference
hashes are in the [MP4 fixture documentation](../tests/Mediana.Tests/Data/Mp4/README.md).

Interlaced reconstruction, custom scaling matrices and transform bypass remain
open decoder work. The encoder continues to accept eight-bit 4:2:0. These checks
establish progressive decoding correctness; they do not establish High10 speed
parity with another decoder.

## Eight-bit encoding regression measurement

A frozen .NET 11 Native AOT build before the precision extension and the final
build encode six complete 150-frame inputs. Both use the same CABAC,
RateDistortion, QP26 starting point, matched bitrate, GOP60 and deblocking
settings from the [encoding matrix](h264-encoding-matrix.md). Each case runs
three fresh processes per build in ABBAAB order, pinned to logical CPU 11 on an
Intel Core i5-12450H with nice -20 and one execution CPU. All 36 complete
MPEG-TS files match the earlier independently decoded bytes exactly.

| Input | Before / after CPU, s | Before / after wall, s | Before / after peak RSS, MiB | Before / after managed allocation, MiB |
| --- | ---: | ---: | ---: | ---: |
| camera-720 | 7.325 / 7.015 | 7.327 / 7.020 | 23.500 / 23.625 | 14.949 / 14.956 |
| noise-720 | 6.446 / 6.263 | 6.450 / 6.266 | 23.875 / 23.625 | 15.139 / 15.081 |
| text-720 | 2.055 / 2.061 | 2.060 / 2.062 | 23.250 / 23.250 | 14.647 / 14.646 |
| photo-pan-1080 | 10.081 / 11.039 | 10.091 / 11.041 | 37.250 / 37.125 | 37.831 / 37.831 |
| animation-1080 | 7.686 / 7.603 | 7.688 / 7.605 | 36.625 / 36.750 | 37.217 / 37.335 |
| cuts-1080 | 13.680 / 13.020 | 14.554 / 13.275 | 36.750 / 36.875 | 37.209 / 37.332 |

Photography has the widest initial timing variation: 10.016–10.842 seconds
before and 10.063–11.695 seconds after. Ten further alternating complete encodes
(five per build) give median CPU 10.169 versus 10.081 seconds, or -0.86%. Their
output bytes also match. The initial +9.50% median increase does not reproduce
in that second series. These shared-host timings do not establish a universal
acceleration or a zero-regression bound; peak memory and cumulative allocation
remain comparable across the measured cases. This is a regression comparison
for the precision extension, not a .NET 10 versus .NET 11 runtime comparison.
