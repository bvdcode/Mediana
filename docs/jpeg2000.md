# Managed JPEG 2000 decoding

`Mediana.Codecs.Jpeg2000` is an original C# decoder targeting .NET 10. It accepts JP2 containers and raw JPEG 2000 Part 1 codestreams. It depends only on Mediana code and the BCL. The implementation was adapted from the same author's MIT-licensed Render.NET codec at commit `03cb502`; it builds independently in this repository. The module is currently available as a source project.

```csharp
using Mediana.Codecs.Jpeg2000;

Jpeg2000Image image = Jpeg2000Decoder.Decode(
    await File.ReadAllBytesAsync("scan.jp2"),
    new Jpeg2000DecodeOptions { MaximumPixels = 4_000_000 },
    cancellationToken);

Jpeg2000Component red = image.GetComponent(0);
ReadOnlyMemory<int> nativeSamples = red.Samples;
int sample = image.GetSample(x: 20, y: 10, component: 0);
```

The result retains integer precision, signedness, and each component's native sampling grid. `GetSample` expands subsampled components with nearest-neighbour lookup. Reversible and irreversible multiple-component transforms are reconstructed before samples are returned. The optional `ToVideoFrame` method explicitly reduces supported gray/sRGB/sYCC components to straight sRGB RGBA8. Raw codestreams require a caller-supplied color interpretation; ICC conversion remains unsupported. `ColorSpace`, `AlphaComponent`, `PremultipliedAlpha`, and `HasIccProfile` describe container metadata; the component API does not perform ICC conversion or alpha compositing.

## Implemented subset

| Area | Support |
| --- | --- |
| Container | JP2 signature, compatible brand, image header, codestream, enumerated sRGB/gray/sYCC, whole-image alpha definition, 32/64-bit box lengths |
| Components | 1–16 components, 1–16-bit signed/unsigned samples, component subsampling, nonzero image/tile origins |
| Wavelets | Reversible 5/3 and irreversible 9/7; up to 16 decomposition levels |
| Coding | MQ arithmetic decoding, significance/refinement/cleanup passes, raw bypass, context reset, termination per pass, vertical causality, predictable termination coding, segmentation symbols |
| Packets | LRCP, RLCP, RPCL, PCRL, CPRL; quality layers, precincts, tile-parts, SOP/EPH |
| Quantization | No quantization, scalar derived, scalar expounded; component overrides; ROI maxshift |

POC progression changes, PPM/PPT packed packet headers, JP2 palettes/component remapping, arbitrary channel remapping, coding changes across tile-parts, extended profiles/Part 2 transforms/HTJ2K, and larger precision/decomposition limits are explicitly unsupported. Predictable termination is decoded, but its termination pattern is not separately validated. The decoder is not an encoder or a complete codestream integrity validator.

Malformed/truncated structures and configured resource-limit violations produce `InvalidDataException`. Unsupported features produce `NotSupportedException`; cancellation produces `OperationCanceledException`.

## Limits and verification

Defaults bound encoded bytes to 128 MiB, reference-grid pixels to 16,777,216, packets across the image to 1,000,000, and cumulative working allocations to an estimated 512 MiB. `ExpectedWidth` and `ExpectedHeight` validate dimensions before sample-buffer allocation. Cancellation is checked during marker/packet interpretation, coding passes, wavelet reconstruction, and sample assembly. The allocation budget accounts for sample buffers and estimates metadata; it is not a hard process-memory cap.

The implementation follows the algorithms and format definitions in [ITU-T T.800 (11/2015), JPEG 2000 Part 1](https://www.itu.int/rec/T-REC-T.800-201511-S). No reference decoder source was incorporated.

`tests/Mediana.Tests/Data/Jpeg2000` contains 70 original synthetic cases and expected pixels decoded independently by OpenJPEG 2.5.4, with recorded hashes. The reversible cases match exactly; the three irreversible/modified-quantization cases allow a maximum difference of one component level. Tests also exercise cancellation, resource limits, malformed headers, unsupported extensions, and concurrent decoding. This coverage does not establish complete standard conformance or production throughput. OpenJPEG and Pillow are development tools only and are not included in package contents or dependencies.
