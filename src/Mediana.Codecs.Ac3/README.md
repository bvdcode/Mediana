# AC-3 and E-AC-3 decoding

`Ac3DecoderFactory` and `Eac3DecoderFactory` implement the shared `IAudioDecoderFactory` contract. AC-3 consumes one complete syncframe per `MediaPacket` with `StreamFormats.Ac3`. E-AC-3 accepts complete synchronized frame sets for one main independent programme, totalling at most six audio blocks, with `StreamFormats.Eac3`. Each frame set contains its independent syncframe followed by up to eight ordered dependent syncframes. These self-describing representations use an empty external configuration.

MP4 uses the explicit `StreamFormats.Ac3Mp4` and `StreamFormats.Eac3Mp4` representations with the original `dac3` or `dec3` payload. Their access units contain exactly six audio blocks. The factories validate that syncframes agree with the configured sampling format. `Ac3StreamMetadataReader` and `Eac3StreamMetadataReader` inspect these configurations independently of decode support; the latter reports the main independent presentation, including declared dependent channel locations. Multiple independent presentations and associated-service mixing produce explicit decoder refusals.

Output is native-endian, interleaved float32 PCM. The main coded channel order is preserved, with explicit labels from `Ac3FrameHeader.GetChannelOrder()`. Dependent substreams replace matching locations and append additional labelled locations, up to 16 output channels. For 5.1 this is left, centre, right, left surround, right surround, LFE. There is no implicit downmix or sample rate conversion.

The decoder synthesizes all syncframes in an access unit directly into one PCM buffer and returns one `AudioFrame`. Each dependent substream has persistent spectral and overlap state, while synthesis writes directly into its final interleaved channel slots. Replaced main channels do not create temporary PCM buffers. Only the independent syncframes advance the programme sample clock. It preserves the packet timestamp and validates presentation durations against whole samples within the combined coded audio. Clipping applies to the access unit once. E-AC-3 output is delayed by at least 5,120 coded samples so later transient metadata can correct retained PCM before publication. Callers must drain available output and call `CompleteInput` at EOF; one accepted packet does not imply immediately available output. Published frames remain immutable, and retained PCM history shares their ownership without making a second audio copy.

`IPacketPrerollDecoder` requests one preceding packet for AC-3 and an initial 26 packets for E-AC-3. The latter warms transform overlap and the bounded transient history even with 256-sample packets. E-AC-3 tracks unresolved history dependencies through each actual transient reconstruction. A seek whose requested PCM still depends on unavailable earlier history is explicitly refused, rather than returning approximate samples; 26 packets are not a universal recovery guarantee. Starting at the original first packet permits shorter preroll and preserves ordinary startup priming. Container edits and encoder padding remain separate from decoding.

Both implementations validate frame length and the complete-frame CRC before decoding. Cancellation or malformed input faults the codec until `Reset` or disposal. Output already delivered to the caller remains independently owned.

## Supported tools

- AC-3 bitstream versions up to eight, 32/44.1/48 kHz, all eight base channel modes and optional LFE.
- Differential exponent strategies D15/D25/D45 and reuse.
- Normative fixed-point bit allocation, delta bit allocation and grouped/signed mantissas.
- Standard channel coupling with coupling bands, coordinates and stereo phase restoration.
- Stereo rematrixing; deterministic, channel-independent dither where signalled.
- Long and switched short inverse transforms, Kaiser-Bessel-derived window and persistent overlap.
- Line-mode dynamic range control, enabled by default. Pass `applyDynamicRangeCompression: false` to a factory to preserve the encoded dynamic range. Dialogue normalization and RF compression metadata do not change PCM gain.
- E-AC-3 backward-compatible bitstream versions 11–16, independent or AC-3-converted substreams using conventional transforms and coupling, all four block counts, frame/block exponent and SNR strategies.
- E-AC-3 dependent channel replacement and extension, explicit or base channel maps, up to eight dependent substreams and 16 rendered channels. The last dependent substream supplies line-mode dynamic range control for the complete programme.
- E-AC-3 adaptive hybrid transforms with every six-dimensional vector codebook, all four gain-adaptive quantization modes, and long/short synthesis. Cached six-block spectra reserve 12 KiB per participating channel on first use.
- E-AC-3 spectral extension with band merging, reused coordinates, noise blending and attenuation filters; it composes with stereo rematrixing and both coupling modes.
- E-AC-3 enhanced coupling with all 22 sub-bands, default/custom merging, compact amplitudes, per-channel reuse and low-frequency rematrix boundaries. Amplitude storage reserves 880 bytes on first use.
- E-AC-3 transient pre-noise processing with future-frame locations, per-channel time scaling, amplitude-preserving Hann crossfades and a bounded 8,192-sample history. Corrections follow metadata order even when later signalled transients have earlier sample positions. Input ending before a signalled future transient can be completed is rejected.

Channel ownership and the number of dependent substreams must remain stable within a decoder session; a changed layout requires a new decoder. An access unit must contain complete frame sets, including every configured dependent substream. Reserved syntax is rejected. The sample rate code reserved by ETSI TS 102 366 is rejected rather than interpreted as a reduced-rate extension.

## Verification

The dedicated test project compares decoded PCM to independently decoded FFmpeg float32 references. It covers mono, stereo and 5.1 at the three sample rates, coupled and uncoupled spectra, all four E-AC-3 block counts, long/short transitions, and exponent reuse. Controlled conventional-transform inputs without dither exceed 135 dB differential SNR. Adaptive-transform long/short vectors exceed 100 dB against the fixed-point reference; the normative quantizer corpus matches its independent mathematical float32 reference exactly. Spectral-extension reference inputs cover stereo rematrixing, standard coupling, band merging and both attenuation extremes; their differential SNR exceeds 139 dB. Enhanced coupling sequences cover every start-frequency code, default/custom bands and spectral-extension composition; their independent direct-DFT float32 references match exactly on the tested runtime. Transient processing is checked against an independent time-scaling reference on a ten-frame long/short sequence; differential SNR exceeds 141 dB. Maximum future-location bursts, grouped access units, immutable published output, bounded storage, flush and unresolved recovery are tested separately. The same transient sequence passes continuous MP4 decoding, indexed seeking and HLS audio preparation/encoding with exact sample counts. Dependent composition is checked against independent direct-DFT references for four-frame 8- and 16-channel sequences. Tests cover channel replacement, extension, absent custom maps, eight ordered dependents, programme-wide gain, resource failure, exact raw/MP4 clocks and indexed seeking. Noise blending is checked against the banded energy envelope with a conforming independent random sequence. Dither uses an independent sequence permitted by the specification, so dithered outputs are compared by error and signal energy rather than bit identity.

Contract tests cover backpressure, timestamps, clipped presentation, preroll, retained output, cancellation, reset, corruption, allocator failure and zero additional spectral/synthesis workspace allocation during repeated decoding.

The implementation follows [ETSI TS 102 366 V1.4.1](https://www.etsi.org/deliver/etsi_ts/102300_102399/102366/01.04.01_60/ts_102366v010401p.pdf), particularly clauses 4, 6.1–6.5, 6.7, 6.9–6.10 and Annex E. No native codec or external decoder is used by the library.

The AHT quantizer reference follows ETSI TS 102 366 Table E.3.4, including all 32 entries of codebook 4. The tested FFmpeg 6.1.1 output differs for that codebook: its table begins with the standard's second row. The first row is present in both ETSI V1.3.1 and V1.4.1. This corpus uses an independent direct-DFT mathematical PCM reference and is not reported as agreement with that FFmpeg version.
