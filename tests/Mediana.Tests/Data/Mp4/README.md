# MP4/MOV fixtures

The clips contain generated test patterns and tones, with no external source media.
They exercise AVC High with B-frames and AAC mono in fast-start MP4, and AVC Baseline
video-only MOV with the movie metadata after the media data.

The checked-in JSON files record source SHA256, stream configuration hashes and
every packet's original media PTS/DTS, duration, size, position, sync flag and SHA256.
Edit-list application is disabled in the reference command so packet times remain
in the track's original media timeline. The reader exposes edits separately.

For `avc-aac.mp4`, the linear movie timeline subtracts 4096 video ticks at
1/10240 seconds and 1024 audio ticks at 1/48000 seconds. Applying edit lists in
ffprobe independently confirms all 84 translated packet PTS/DTS. The managed and
Native AOT checks preserve every compressed packet while merging by translated
decode time. Both timestamp modes are also checked through MPEG-TS stream copy.

Generation used FFmpeg/ffprobe 6.1.1. These tools are used to prepare and independently
inspect fixtures; building and running Mediana and its tests does not require them.
Encoder versions can change the generated bytes; use the corresponding reference
JSON when updating a fixture.

`avc-segments.mp4` contains 7.2 seconds of 64x48 AVC with B pictures, one closed
GOP per second and mono AAC. Its SHA256 is
`3a79f59fa68f58d51b940b1c087a934581de5b3688b846a0a5a554e9f776f2c4`.
The companion JSON records every one of its 375 packets. Inspected IDR samples
are 0, 5, 10, 15, 20, 25, 30 and 35. A 2.25-second target selects video windows
0..15, 15..30 and 30..36, with movie presentation starts 0, 3 and 6 seconds and
durations 3, 3 and 1.2 seconds. Independent decoding of each window matches every
one of the corresponding source's 36 YUV pictures, including B-picture reorder.

The B headers at video packet indices 2 and 3 are checked against FFmpeg 6.1.1
`trace_headers`, including both active reference counts, picture order, direct
prediction selection, quantizers, reference marking and CABAC alignment. The
same checks run in Native AOT. Complete reconstruction now also matches every
sample in `avc-segments.sequence.yuv`, including reference B pictures. The public
session verifies all 36 pictures, presentation order, PTS, duration and released
storage. `avc-aac.sequence.yuv` supplies the same checks for all eight pictures
of the fast-start input. Each packed YUV420 picture occupies 4608 bytes.
The first five parsed headers also verify the POC sequence 0, 6, 2, 4, 8 and
reference retention. At packet 2, L0/L1 select frame numbers 0/1. At packet 3,
L0 selects 2, 0 and L1 selects 1. These list checks use allocated picture storage
without reconstructing the B slice payload.

| Packet | frame_num | POC LSB | Active L0/L1 | nal_ref_idc | QP |
| --- | --- | --- | --- | --- | --- |
| 2 | 2 | 2 | 1/1 | 2 | 26 |
| 3 | 3 | 4 | 2/1 | 0 | 28 |

```sh
ffmpeg -hide_banner -loglevel info -i avc-segments.mp4 -map 0:v:0 -c:v copy -bsf:v trace_headers -f null -
```

```sh
ffmpeg -v error -nostdin -f lavfi -i testsrc2=size=64x48:rate=5:duration=7.2 -f lavfi -i sine=frequency=440:sample_rate=48000:duration=7.2 -map_metadata -1 -c:v libx264 -preset medium -pix_fmt yuv420p -g 5 -keyint_min 5 -sc_threshold 0 -bf 2 -x264-params open-gop=0 -c:a aac -b:a 64k -shortest avc-segments.mp4
```

```sh
ffmpeg -v error -nostdin -y -f lavfi -i testsrc2=size=64x48:rate=5:duration=1.6 -f lavfi -i sine=frequency=440:sample_rate=48000:duration=1.6 -map_metadata -1 -c:v libx264 -preset medium -pix_fmt yuv420p -g 5 -bf 2 -c:a aac -b:a 64k -movflags +faststart -shortest avc-aac.mp4
```
